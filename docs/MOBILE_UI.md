# Мобильный интерфейс по образцу пользователя

Обновлено 27.10.2026. Источник — прикреплённый в чате общий снимок десяти экранов.
Код/слои Figma по-прежнему недоступны из-за лимита интеграции. Поэтому проверка
визуальная по предоставленному растровому образцу, без заявления о точном совпадении
с исходными размерами и ассетами Figma.

Компоновка включается при ширине окна до 1023px, в том числе на узких Android-планшетах.
Привязки к user-agent нет: изменение ориентации или размера окна корректно переключает
вариант интерфейса. Начиная с 1024px используются прежние desktop-экраны.

Основные снимки получены Playwright на viewport 390×844 с Android-профилем Pixel 7.
[Дополнительный снимок планшета 800px](screenshots/android-tablet-800.png).
Это эмуляция браузерного профиля, а не проверка на физическом Android-устройстве.

Отличия, необходимые для работы приложения:

- Настройки доступны через небольшую иконку в шапке.
- Время хранится в SQLite, поэтому сообщение о хранении описывает SQLite.
- Даты, имена, часы, количество сотрудников и записей берутся из API и могут
  отличаться от демонстрационных значений в образце.
- По нажатию на карточку журнала доступны подробности, редактирование и удаление;
  полное описание сохраняется, даже если строка в карточке сокращена.
- Даты редактируются внутри раскрываемого поля «Период»; статус журнала — там же.
  Фильтр сотрудника в отчётах открывается иконкой рядом с периодом.
- Архивные сотрудники доступны через раскрываемые фильтры списка.
- Для пустого отчёта дополнительно показан нулевой итог; разрушительные операции
  по-прежнему требуют подтверждения.

Сценарии `tests/e2e/mobile.spec.ts` проверяют десять состояний, отмену/сохранение формы,
reload и повторный старт таймера, карточки журнала, CSV, JSON, восстановление и сетевую
ошибку. Отдельно проверены длинное описание и ширины 320, 390, 800px; профиль
дополнительно проверяется на 768px. Данные тестов изолированы от основной базы.
