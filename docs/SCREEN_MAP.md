# Карта экранов WorkTime

Источник требований: WORKTIME_CODEX_TZ.md v1.0, предоставленное пользователем 26.10.2026.
Дизайн: https://www.figma.com/design/Cj8MbOLCq4FAeI19G9aMj3

Доступ к get_design_context и get_screenshot заблокирован лимитом Figma Starter.
Поэтому интерфейс реализуется по письменным токенам и составу экранов; точное
визуальное соответствие и Figma-ассеты пока не подтверждены. Код макетов не получен.

| Состояние из ТЗ                             | Маршрут / реализация                                            |
| ------------------------------------------- | --------------------------------------------------------------- |
| 1. Главная                                  | `/`, сводка за последние семь календарных дней, недавние записи |
| 2–3. Таймер ожидает / работает              | `/timer`, форма и активные сессии из API                        |
| 4. Диалог запуска                           | Подтверждение перед стартом на `/timer`                         |
| 5–6. Сотрудники / добавление                | `/employees`, поиск, диалог формы                               |
| 7. Профиль                                  | `/employees/:id`, статистика, записи, редактирование и архив    |
| 8. Пустая команда                           | `/employees`, приглашение создать сотрудника                    |
| 9. Журнал                                   | `/entries`, сотрудник, даты, статус, пагинация                  |
| 10–11. Изменение / удаление записи          | Диалог формы и подтверждение в журнале                          |
| 12–14. Отчёты команды / сотрудника / пустые | `/reports`, период, график, таблица, нулевое состояние          |
| 15. Хранение и резервные копии              | `/settings`, SQLite, JSON, импорт replace, очистка              |
| 16. Ошибки полей                            | Нативные ограничения форм и серверные сообщения в диалоге       |
| 17. Подтверждение остановки                 | Диалог с именем, задачей, отсчётом                              |
| 18. Уведомление сохранения                  | Закрываемый toast после успешного ответа API                    |

Обновление 27.10.2026: пользователь предоставил снимок 10 мобильных состояний.
Компактная версия до 1023px включительно повторяет его структуру и использует
нижнее меню Обзор / Таймер / Команда / Журнал / Отчёты. Настройки доступны в шапке.
Форма новой сессии — `/timer/new`, нового сотрудника — `/employees/new`.
На обзоре показаны сегодня, активные сессии, численность команды и последние 7 дней.
Списки команды и журнала представлены карточками, отчёт — полосами по сотрудникам.
Настройки используют три блока: хранение, восстановление, очистка. Данные по-прежнему
получаются из API. Полная карта новых состояний — [MOBILE_UI](MOBILE_UI.md).
